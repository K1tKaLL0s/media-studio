# 网页审美方向

先看现有页面/截图/设计系统及用户要求，分清“新视觉方向”“保留设计的局部改进”“复现指定参考”。未实际看到界面时只做方向方案，不宣称评审了真实产品。功能 bug 不自动启动本 Skill，指定设计复现不另创风格。

1. 定义页面首要任务和三秒内应读到的信息。写主次内容、主要操作及完成后的反馈；视觉焦点帮助用户行动，不让装饰、状态和主按钮争抢同一强调色。
2. 定一个合适方向：编辑式、工具式、展陈式或用户提供方向，说明其与内容/受众的联系。把方向落实为网格、间距节奏、字体角色、主次色、边框/材质、图片策略；不要只交一串风格词。
3. 用角色规定排版：页标题、段标题、正文、标签、数值/代码分别解决什么阅读问题；优先既有可用字体与中文完整覆盖，考虑回退后的换行。密集工具页面不为醒目牺牲可扫读性。
4. 定义明暗/强调色及 hover、focus、disabled、loading、empty、error 的视觉关系。检查正常文本对比与必要的动效关闭方式，细则见 [review.md](references/review.md)。选色本身不能证明可访问性合规。
5. 用内容真实长度检查桌面和窄屏；给标题长文、表格、错误文案、空内容留位置。素材应体现页面功能或品牌，生成背景图交 media-image-prompts，不把带文字的整张栅格图当可交互网页。

输出一页视觉简报：目标与焦点、布局规则、字体角色、色板职责、素材/动效原则、状态示例和验收方式。用户已经给出系统时写允许修改项与保留项，避免无关换肤。

进入实现：可选的已安装 frontend-design 技能适合建立前端视觉；明确的 Product Design 或 Figma 请求按对应已安装 Skill 路由，不仅因网页二字就并行启动所有插件。长期代码遵守用户宿主与当前项目的代码执行规则并交付执行书，UI模型/代理分工遵从已覆盖本次任务的用户决定。

评审按证据写：在哪个视口、哪个状态看到什么，影响哪个任务，具体怎么改。静态截图能支持排版和图文遮挡判断，不能证明键盘导航、读屏、性能或所有状态通过。没有运行的检查保留待测，不用主观“高级感”掩盖无法使用的界面。
